# Socializando — Gestão de Oficinas v4.6.0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Adicionar à LP existente do Socializando um módulo de oficinas com vagas dinâmicas, inscrição, Pix direto e confirmação administrativa, preservando integralmente o design-base e as artes aprovadas.

**Architecture:** A LP permanece estática no GitHub Pages e recebe uma seção funcional de oficinas. Supabase/PostgreSQL armazena turmas de oficinas e inscrições; cada turma é uma linha em `workshops`, agrupada por `experience_key` quando pertence à mesma experiência; chamadas públicas usam RPCs `security definer` com validação e token público por inscrição, sem abrir acesso direto aos dados pessoais. O QR Code Pix é gerado no navegador conforme BR Code, usando a chave CNPJ aprovada; apenas inscrições com status `confirmed` reduzem as vagas.

**Tech Stack:** HTML/CSS/JavaScript existentes, módulos ES, Node.js built-in test runner para lógica pura, Supabase/PostgreSQL, QR Code renderizado no navegador sem gateway de pagamento.

**Spec:** `oficinas/README.md`

## Global Constraints

- Não alterar o design-base da LP além da inclusão do módulo funcional de oficinas.
- Não redesenhar, editar, recortar, recolorir ou reinterpretar as duas artes aprovadas.
- Oficina Expedição Jurássica: 10/10/2026, 14:00–15:30, a partir de 5 anos, R$ 50,00, 15 vagas.
- Oficina Fábrica dos Squishy Mágicos: 10/10/2026, 15:30–17:00, a partir de 5 anos, R$ 50,00, 15 vagas.
- A arquitetura deve aceitar segunda turma da mesma oficina em data diversa, com contador independente.
- Artes que contenham data/horário impressos são específicas daquela turma: nova data não pode herdar a arte anterior; exige novo asset aprovado ou permanece sem imagem.
- Pix CNPJ: `59.380.867/0001-62`.
- Cadastro não ocupa vaga.
- `payment_reported` não ocupa vaga.
- Somente `confirmed` ocupa vaga.
- Sem gateway de pagamento e sem taxa de intermediador no MVP.
- WhatsApp oficial permanece `+55 53 99951-9569`.
- Desenvolvimento somente na branch `feature/oficinas-v4.6.0`; não publicar na `main` antes de aprovação.

## Review Focus

- Concorrência na última vaga: duas pessoas podem pagar quando ainda existe uma vaga; confirmação deve nunca ultrapassar capacidade e a interface deve explicar que pagamento informado não equivale a confirmação.
- Reenvio de ação “Já fiz o Pix”: deve ser idempotente e não duplicar inscrição nem alterar uma inscrição já confirmada/cancelada.
- QR Pix: CNPJ, valor de R$ 50,00, TXID e CRC16 devem produzir payload válido e determinístico.
- Dados pessoais: acesso anônimo não pode listar inscrições, e o token público não pode conceder leitura de PII.
- Falha/ausência do Supabase: a LP principal deve continuar funcionando; o módulo deve mostrar indisponibilidade operacional sem inventar contador de vagas.
